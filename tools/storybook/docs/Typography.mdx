# Typography

Every size, weight and family below is read from the running page. The steps are discovered from the
token names rather than listed here, and ordered by their resolved pixel value — so adding
`--heading-3xl` or a new weight to `tools/sass/global/_variables.scss` puts it on this page with
nothing to update.

The scale is **fluid**. Each size is a single `clamp()` that interpolates between a phone value and a
desktop value across the viewport range, so type grows continuously with the page rather than jumping
at a breakpoint. Each step below prints the expression and what it resolves to at the width you are
reading at — drag the canvas and both the specimen and the number follow.

## Line height

Line heights are unitless — a multiple of the font size rather than a fixed pixel value. That pairs
with the fluid sizes: as a heading interpolates down towards its phone value its leading follows it,
instead of growing tight against a pixel value chosen for the desktop end.

## Using these

- Set type through the `Text` component's `variant` and `size` props rather than a raw `font-size`.
  The props map to these tokens; a literal does not, and will not follow a change to the scale.
- There is no breakpoint to write. A size token already covers the whole viewport range, so a media
  query that steps type down is re-solving a solved problem — and reintroduces the jump the fluid
  scale removed.
- The bounds of every clamp are expressed in `rem`, so a reader who raises their browser's base font
  size scales the whole system with them. Keep it that way: a `vw`-only formula would ignore that
  setting and fail WCAG 1.4.4.
